[s1.4] A Preliminary Sequential Changepoint Detection Information

[s1.5] Before proceeding with our framework, we first introduce the sequential changepoint detection paradigm used in this paper for identifying a mean change in a generic sequence of data {Yt : t = 1, 2, . . .}. We present the general setup introduced in Chu et al. (1996), along with the detector used for detecting changes; Page’s CUSUM detector (Page, 1954). Moreover, we highlight the key large-sample results from the literature which we utilize within our framework.

[s3.1] The hyper-parameter γ allows a practitioner to tune the stopping time dependent upon when the change is likely to take place. If the change is likely to occur early in the process then increasing γ will lead to a faster detection time, however, if the change occurs later in the process then having a larger γ will decrease the detection time. Throughout this paper, we assume γ = 0 for simplicity but for a more detailed discussion, see Horváth et al. (2004).

[s5.1] C Additional Simulation Results C.1 Mean Change

[s5.2] First, we explore mean changes in the underlying data generating process. We generate two scenarios where the data is generated from:

[s5.3] 1. An AR(2) process with ϕ = (0.5, −0.3), λ = 0 and σ2 = 1.

[s5.4] 2. An ARMA(1,1) process with ϕ = 0.6, θ = 0.3, λ = 0 and σ2 = 1.

[s5.5] For both scenarios we generate data of length n = 1000, with ntrain = 200. We set m = 200 as the training period for the detectors and once monitoring begins, we introduce a changepoint of size δµ to the process at k∗ = 100. This leaves 500 time points for the methods to identify if a change has occurred. Note as Raw CUSUM does not require any training of the model the first ntrain = 200 time points are not used by this method. For clarity, to generate the data we used the arima.sim function from the stats package with an extra 50 time points for burn-in that is removed before analysis begins. For ARMA Forecast Errors, we assume the order of the data generating process is known and the parameters are estimated within the training period.

[s5.6] Figure 1 shows the DP, FDP and ADD of the 2 methods. For both models, we can clearly see the ADD when using the ARMA Forecast Errors is much lower than using the Raw CUSUM across all change sizes. Additionally, the DP for the ARMA Forecast Errors is at least as big as for the Raw CUSUM while both have comparable FDP. These metrics show that for the mean changes presented here using ARMA Forecast Errors has a distinct advantage over the Raw CUSUM. C.2 Variance Change

[s5.7] Now we examine variance changes in the underlying data generating process. Again we generate two scenarios, where the data is generated from

[s5.8] 1. An AR(1) process with ϕ = 0.9, λ = 0 and σ2 = 1.

[s5.9] 2. An ARMA(2,1) process with ϕ = (0.5, −0.3), θ = 0.6, λ = 0 and σ2 = 1.

[s5.10] Here n, ntrain, m and k∗ are the same as in Section C.1 (n = 1000, ntrain = 200, m = 200, k∗ = 100). Again, for the ARMA Forecast Errors, we assume the order of the ARMA process is known but the parameters need to be estimated. For the ETS Forecast Errors, we assume an ETS(A,N,N) model and the smoothing parameter is to be estimated. The change size, δξ, represents the new variance in the underlying data process after the change has occurred.

[s5.11] Figure 2 shows that in both scenarios the ADD is nearly always smaller when using ARMA Forecast Errors or ETS Forecast Errors than the Raw CUSUM. The reason the ADD for the Raw CUSUM is lower in the AR(1) scenario with change size δ = 1.5 is probably due to the small DP. This is also evidenced by the standard error bars overlapping with those from ARMA Forecast Errors. 5
